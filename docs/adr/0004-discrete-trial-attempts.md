# The Trial system uses discrete accusation windows, not ToS2's continuous voting

Town of Salem 2's real trial system lets players nominate/accuse continuously throughout a single, open-ended Day phase - accusations accumulate live, and the moment one crosses a majority threshold, the game breaks into that trial's Defense/Judgment right then, with no fixed "accusation window." This game's Day is instead built from fixed-length phases (`GamePhase` values, each with its own Firestore-synced `phaseDeadline`), so a genuinely continuous, un-timed accusation stream doesn't fit the existing architecture without a much larger rework (open-ended phases, live accusation state pushed to every client outside the normal phase-poll model, etc.).

The chosen adaptation: `LobbyDoc.trial.trialNumber` counts discrete accusation *attempts* (1 to `MAX_TRIALS_PER_DAY`, currently 3), not just attempts that reached a Judgment. Each attempt gets its own fixed-length Accusation phase (`ACCUSATION_DURATION_MS`); if majority is reached, that attempt proceeds through Defense and Judgment; if not (timeout, or everyone's voted without reaching majority), the attempt is spent and a fresh Accusation phase begins immediately, up to the limit. Only a Guilty verdict short-circuits the loop early. This preserves ToS2's actual player-facing shape - "up to three chances to catch someone, each with its own accuse-then-judge rhythm" - without requiring a genuinely open-ended, continuously-polled phase.

Two other scoping decisions rode along with this and are worth recording here rather than only in code comments, since they narrow existing mechanics in ways a future reader might not expect:

- **The Puppeteer's override now only applies to a Judgment vote.** Previously it could target any day-phase vote, including Overtime's. Overtime kept its old simple-target-vote shape entirely (it never uses the Trial loop), so if a game reaches Overtime without ever having had a successful Accusation, the Puppeteer's ability goes unused for that game. Extending the override to also cover Overtime's vote, or the Accusation vote, were both considered and rejected as unnecessary complexity for what's already a rare edge case (Overtime itself requires the cycle cap to be reached).
- **The Tome-holder's investigation immunity was removed in an earlier, unrelated change** (see git history) - not part of this ADR, but relevant context: Trial-phase Researcher investigations are unaffected by who holds the Tome; only a Framer can make a result wrong.

## Consequences

A day can now take meaningfully longer than before - up to 3 full Accusation/Defense/Judgment cycles (`60s + 20s + 30s` each) versus the old single 60s vote, though in practice most days will resolve in one or zero trials. Any future change to `MAX_TRIALS_PER_DAY`, or to whether Overtime should also use trials, should revisit this ADR's reasoning rather than being made as an isolated tweak, since the discrete-attempt model was chosen specifically to fit the existing fixed-phase architecture - a switch to genuinely continuous accusation would need to revisit that architectural assumption too.
